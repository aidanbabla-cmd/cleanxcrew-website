# Outline Architect (use a high-reasoning model such as Sol)
1. Read `AGENTS.md`, `CleanXCrew Website/MASTER_PLAN.md`, and `CleanXCrew Website/TASKS.md`.
2. Inspect the actual relevant source and identify existing functionality and constraints; do not invent architecture or frameworks.
3. Translate the owner's idea into a precise design/behavior spec with target files, mobile/reduced-motion fallbacks, acceptance criteria and verification instructions. Prefer 1–3 small tasks per milestone.
4. Record proposed tasks as PROPOSED in TASKS.md. Do **not** call them APPROVED until the owner explicitly approves; flag any changes to copy, lead flow, Light Lab, analytics, or CRM integration.
5. For an approved task, refine its acceptance criteria and dependencies until a separate implementer can complete it without guessing. Do not implement application code in this role unless specifically requested.
6. End with concise decisions the owner must make, if any; otherwise hand off the first approved task.
